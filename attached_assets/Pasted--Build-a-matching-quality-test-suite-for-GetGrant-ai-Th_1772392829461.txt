 
Build a matching quality test suite for GetGrant.ai.
This is a standalone test script — do NOT modify production code.
 
CREATE FILE: scripts/test-matching-quality.ts
 
PURPOSE:
 Run 10 predefined company profiles through the live matching engine
 and output a structured quality report. The report shows which grants
 were returned, their scores, and flags potential problems automatically.

SECTION 2 — TEST RUNNER LOGIC
═══════════════════════════════════════════════════════════════
 
For each company in TEST_COMPANIES, the test runner should:
 
1. Create a temporary in-memory company object matching the profile.
  Do NOT insert into the database. Use the existing matching functions
  directly by passing the company object as a parameter.
 
2. Call the matching function from client/src/lib/matching.ts
  (or the equivalent server-side function) with the temp company
  and retrieve the full list of grants with scores.
  Sort by score descending. Take top 20.
 
3. Run these automated checks:
 
  CHECK A — Relevance (top 10):
    For each sourceName in the top 10 results,
    check if any expectedInTop10 keyword appears in the sourceName (case-insensitive).
    Count how many expected sources appear.
    PASS if count >= Math.ceil(expectedInTop10.length * 0.6)   // 60% hit rate
 
  CHECK B — Exclusion (top 10):
    For each grant in top 10, check if any expectedNotInTop10 keyword
    appears in sourceName or grant title (case-insensitive).
    PASS if zero exclusions appear in top 10.
 
  CHECK C — Score differentiation:
    score1 = results[0].score  // highest
    score10 = results[9].score // 10th
    spread = score1 - score10
    PASS if score1 >= 65 AND spread >= 25
 
  CHECK D — Market segmentation (only for C9, C10):
    For each grant in top 20, query the grants table for the grant's market field.
    PASS if NO grant with market = forbiddenMarkets appears.
 
  CHECK E — Negative control (only for C8):
    Count grants in top 20 where score > negativeControlScoreThreshold.
    PASS if count < negativeControlMaxHighScores.
 
4. Store results per company as a typed TestResult object.

SECTION 4 — ALSO CREATE: Admin UI endpoint
═══════════════════════════════════════════════════════════════
 
Add GET /api/admin/matching-test to server/routes.ts (admin auth required).
 
This endpoint:
 1. Reads the most recent scripts/matching-test-results.json
 2. Returns it as JSON
 3. If no file exists, returns { 'status': 'not_run', 'message': 'Run test first' }
 
Add a 'Matching Quality' card to the Admin dashboard (admin pages) that shows:
 - Date of last test run
 - Overall pass/fail count (e.g. '8/10 passed')
 - A red badge if any criticalFailures > 0
 - A 'Run test' button that calls:
   POST /api/admin/matching-test/run
   (This endpoint shells out to run the TypeScript test file in background
   and returns immediately with { status: 'running' })
