PROMPT 03  Cache Eligibility Checks to Fix Dashboard Performance
Priority
P0 — Critical
 
Category
Backend / Performance
Effort estimate
3–4 hours
 
Files affected
server/routes.ts  (eligibility-overview endpoint)
server/routes.ts  (PATCH /api/companies/:id — invalidate cache)
db/schema.ts       (add profileHash column to eligibility_checks)
What & Why
The /api/grants/eligibility-overview endpoint currently runs eligibility checks on ALL grants against the user's company profile on every dashboard page load. At 1,700+ grants this is already slow; at 5,000+ grants it will break. The eligibility_checks table already exists — we just need to read from it as a cache, only recomputing when the company profile changes. This is the single most important performance fix before scaling.
📋  Replit Prompt — copy this exactly
 
In db/schema.ts add column to eligibility_checks table:
 profileHash: text('profile_hash')  -- SHA256 of company JSON
Run: npx drizzle-kit push
 
Create helper server/utils/profileHash.ts:
 import crypto from 'crypto';
 export function hashProfile(company: Company): string {
   const key = JSON.stringify({
     industry: company.industry,
     employees: company.employees,
     revenue: company.revenue,
     location: company.location,
     focusAreas: company.focusAreas,
   });
   return crypto.createHash('sha256').update(key).digest('hex');
 }
 
In the GET /api/grants/eligibility-overview handler:
 1. Compute currentHash = hashProfile(company)
 2. Query eligibility_checks WHERE companyId = ? AND profileHash = currentHash
 3. If results cover >=95% of grants -> return cached results immediately
 4. Otherwise -> run eligibility check only on uncached grants,
    save results with profileHash, then return combined set
 
In PATCH /api/companies/:id handler, after saving:
 DELETE FROM eligibility_checks WHERE companyId = ?
 (This forces recompute on next dashboard load after profile edit)
 
Add a response header: X-Cache: HIT or MISS for debugging.
 
Add a background job comment (// TODO: run full recheck nightly via cron)
but do not implement the cron yet — cache invalidation on profile edit
is sufficient for now.
✅  Verification steps
9. Load dashboard, check server logs — first load shows MISS, recomputes.
10. Reload dashboard immediately — should show HIT, respond in <200ms.
11. Edit company profile, reload dashboard — should show MISS again (cache cleared).
12. Verify eligibility_checks rows have profileHash populated.
