Compliance Check
Build an AI compliance checker that reviews a draft application against the 
grant's official evaluation criteria and identifies gaps, weaknesses, and 
missing requirements before submission.

## Overview
After a user has written or AI-generated their application, they can run a 
compliance check. The AI reviews each section against what evaluators actually 
look for and returns specific, actionable feedback — not just "good" or "bad" 
but exactly what is missing and how to fix it.

Inspired by Cogrant Write's compliance checks and Granter.ai's criteria alignment.

## Backend: server/services/complianceChecker.ts
```typescript
import Anthropic from '@anthropic-ai/sdk';

interface ComplianceReport {
  overallScore: number;             // 0-100 readiness score
  readinessLevel: 'not_ready' | 'needs_work' | 'almost_ready' | 'ready';
  sections: SectionCompliance[];
  criticalIssues: string[];         // blockers that will likely cause rejection
  improvements: string[];           // high-impact improvements
  strengths: string[];              // what's already working well
  estimatedSuccessRate: string;     // e.g. "Low (20-30%)" | "Medium (40-60%)" | "High (70%+)"
  checkedAt: string;
}

interface SectionCompliance {
  sectionKey: string;
  sectionTitle: string;
  score: number;                    // 0-100
  issues: ComplianceIssue[];
  suggestions: string[];
}

interface ComplianceIssue {
  severity: 'critical' | 'major' | 'minor';
  issue: string;                    // what's wrong
  criterion: string;                // which evaluation criterion is affected
  fix: string;                      // specific actionable fix
}

export async function checkCompliance(
  grant: Grant,
  application: Application,
  companyProfile: CompanyProfile
): Promise<ComplianceReport> {
  const client = new Anthropic();
  
  // Build the full application text for review
  const applicationText = application.sections
    .map(s => `## ${s.sectionTitle}\n${s.content}`)
    .join('\n\n');
  
  // Get grant-specific evaluation criteria
  const evaluationCriteria = getEvaluationCriteria(grant.source);
  
  const response = await client.messages.create({
    model: 'claude-opus-4-5',
    max_tokens: 2000,
    system: `You are a senior grant evaluator with 15+ years experience reviewing 
applications for ${grant.source}. You know exactly what makes applications succeed 
or fail. Be specific, honest, and constructive. Always respond with valid JSON only.`,
    messages: [{
      role: 'user',
      content: buildCompliancePrompt(grant, applicationText, evaluationCriteria, companyProfile)
    }]
  });
  
  const text = response.content[0].type === 'text' ? response.content[0].text : '{}';
  
  try {
    const result = JSON.parse(text) as ComplianceReport;
    result.checkedAt = new Date().toISOString();
    return result;
  } catch {
    return buildFallbackReport();
  }
}

function getEvaluationCriteria(source: string): string {
  const criteria: Record<string, string> = {
    vinnova: `
      Vinnova evaluates on 4 criteria (equal weight):
      1. RELEVANCE: Does the project address important challenges? Is there a clear 
         societal or economic need? Is the timing right?
      2. SCIENTIFIC/TECHNICAL QUALITY: Is the approach innovative? Is the methodology 
         sound? What is the current TRL and what TRL will be reached?
      3. FEASIBILITY: Is the team competent? Is the plan realistic? Are risks identified 
         and managed? Is the budget reasonable?
      4. IMPACT: What are the expected results? How will results be used and spread? 
         What is the commercialization plan? What is the potential for Swedish 
         competitiveness?
      
      Common rejection reasons: vague impact statements, budget not justified line-by-line,
      team lacks relevant competence, no evidence of market need, too early stage for 
      the call, collaboration requirements not met.`,
      
    tillvaxtverket: `
      Tillväxtverket evaluates on:
      1. NEED AND PROBLEM: Is there a documented market failure? Why can't the market 
         solve this alone?
      2. REGIONAL IMPACT: Does the project create jobs in the region? Does it strengthen 
         regional competitiveness? Is there a clear connection to regional strategy?
      3. ADDITIONALITY: Would the project happen without the grant? Can the company 
         co-finance (typically 50%+)?
      4. SUSTAINABILITY: Will results last beyond the project? Environmental impact?
      
      Common rejection reasons: insufficient regional connection, no co-financing plan,
      project could be funded commercially, unclear job creation numbers.`,
      
    energimyndigheten: `
      Energimyndigheten evaluates on:
      1. ENERGY RELEVANCE: Clear connection to Swedish energy transition goals
      2. INNOVATION LEVEL: Is this genuinely new? What is TRL? 
      3. COMMERCIAL POTENTIAL: Path to market within 5 years?
      4. TEAM: Energy sector competence, relevant partners
      5. ENVIRONMENTAL BENEFIT: Quantified CO2 reduction potential (tonnes/year)
      
      Common rejection reasons: no quantified energy savings, missing industry partner,
      TRL too high (basic research) or too low (already commercial).`,

    generic: `
      Standard grant evaluation criteria:
      1. Problem/need clearly defined with evidence
      2. Solution is innovative and feasible
      3. Team has relevant expertise and capacity
      4. Budget is realistic and well-justified
      5. Expected outcomes are measurable and significant
      6. Sustainability plan beyond the grant period
      7. Compliance with all eligibility requirements`
  };
  
  return criteria[source.toLowerCase()] || criteria.generic;
}

function buildCompliancePrompt(
  grant: Grant,
  applicationText: string,
  evaluationCriteria: string,
  company: CompanyProfile
): string {
  return `Review this grant application for compliance and quality.

GRANT:
Title: ${grant.title}
Funder: ${grant.source}
Description: ${grant.description?.substring(0, 400)}
Max amount: ${grant.maxAmount ? `${grant.maxAmount} SEK` : 'Not specified'}

OFFICIAL EVALUATION CRITERIA:
${evaluationCriteria}

APPLICANT COMPANY:
${company.name} | ${company.sector} | ${company.employees} employees | ${company.region}

APPLICATION TEXT:
${applicationText}

Review each section of the application against the evaluation criteria. 
Be specific — quote or reference actual text from the application when identifying issues.
Focus on what will actually affect the evaluation score, not stylistic preferences.

Respond with JSON only:
{
  "overallScore": 0-100,
  "readinessLevel": "not_ready" | "needs_work" | "almost_ready" | "ready",
  "estimatedSuccessRate": "Low (15-25%)" | "Medium (35-55%)" | "High (65-80%)",
  "criticalIssues": [
    "Specific critical issue that will cause rejection — quote from application if relevant"
  ],
  "improvements": [
    "High-impact improvement with specific action: what to add/change/remove"
  ],
  "strengths": [
    "What the application does well — be specific"
  ],
  "sections": [
    {
      "sectionKey": "section_key",
      "sectionTitle": "Section Title",
      "score": 0-100,
      "issues": [
        {
          "severity": "critical" | "major" | "minor",
          "issue": "What is wrong or missing",
          "criterion": "Which evaluation criterion this affects",
          "fix": "Specific action to fix this: add X, change Y to Z, include data on W"
        }
      ],
      "suggestions": [
        "Optional improvement that would strengthen this section"
      ]
    }
  ]
}`;
}
```

## New API endpoint

Add to `server/routes/applications.ts`:
POST /api/applications/:id/compliance-check

Requires authentication and application access
Runs compliance check (AI call ~5-10 seconds)
Saves result to applications table as jsonb field 'complianceReport'
Returns ComplianceReport

GET /api/applications/:id/compliance-check

Returns latest saved compliance report (no new AI call)
Returns 404 if no report exists yet


Add `complianceReport` field to applications table in schema.ts:
```typescript
complianceReport: jsonb('compliance_report'),
complianceCheckedAt: timestamp('compliance_checked_at'),
```

### "Fix this section" integration

Each critical/major issue has a "Fix this section" button that:
1. Opens the section editor with the issue highlighted
2. Pre-fills the "Regenerate with instructions" field with the specific fix:
   `"Add TRL level statement. Current TRL is [ask user]. Target TRL is [ask user].
    Include this in the methodology paragraph."`
3. User confirms and regenerates that section only

### Score color coding
- 0-50: Red (not ready)
- 51-69: Orange (needs work)  
- 70-84: Yellow (almost ready)
- 85-100: Green (ready to submit)
